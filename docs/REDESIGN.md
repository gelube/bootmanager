# Boot Manager Pro v2.0 重新设计

> 目标：从"能用的工具"升级为"安全、可维护、界面友好"的产品。
> 原则：**渐进重构，不推倒重写**。旧代码继续工作，新结构一层层包上来。

---

## 一、架构设计

### 1.1 目标分层

```
┌─────────────────────────────────────────────┐
│  UI 层  src/ui/                             │
│  卡片式界面。只做展示和交互，不含业务逻辑。      │
│  一页一文件，通过 ops 层调用全部能力。           │
├─────────────────────────────────────────────┤
│  操作层 src/core/ops.c  ★ 新增               │
│  所有破坏性操作的唯一入口。                     │
│  强制：写前备份 → 目标确认 → 执行 → 回读验证。   │
├─────────────────────────────────────────────┤
│  服务层 src/core/（现有模块保留）               │
│  mbr_manager / uefi_nvram / limine / refind  │
│  bcdedit(待迁WMI) / esp / backup             │
├─────────────────────────────────────────────┤
│  基础层 src/utils/                            │
│  bm_result 统一错误码 · 编码转换 · 日志         │
└─────────────────────────────────────────────┘
```

三条铁律：

1. **UI 永远不直接调用服务层**——必须经 ops 层。
2. **破坏性操作必须走 ops 层的完整流程**（见 1.2）。
3. **所有模块对外只报 `BM_RESULT`**，UI 层只需要展示它。

### 1.2 安全事务层（ops.c）—— 本项目最重要的设计

对引导工具，最致命的不是功能缺失，而是"操作错了对象"和"写坏了没退路"。
所有写盘/写 NVRAM 的操作统一为四步事务：

```c
BM_RESULT OpsWriteMbrBootCode(int diskNumber, MBR_BOOT_TYPE type);
// 内部流程：
//  1. Validate : 目标存在、是 MBR 盘、非 GPT、（可选）是系统盘确认
//  2. Backup   : 自动备份当前 MBR 到 backups/auto/<时间戳>_<盘>.bin
//                备份失败 → 中止操作（没有退路就不动手）
//  3. Execute  : 调用服务层实际写入
//  4. Verify   : 回读目标扇区，校验 55AA 签名 + 分区表未变（哈希对比）
//                失败 → 自动回滚（用第2步的备份恢复）
```

适用范围：MBR 引导码写入/恢复、活动分区设置、PBR 写入、NVRAM 启动项增删。
其余只读操作（扫描、查询）直接透传服务层，不套事务。

### 1.3 统一结果码（include/bm_result.h）

```c
typedef struct {
    BM_STATUS   status;        // BM_OK / BM_ERR_*
    WCHAR       message[256];  // 可直接展示给用户的中文消息
    DWORD       win32Error;    // 原始 GetLastError()，便于诊断
} BM_RESULT;
```

消灭现有的四种并存风格（bool+error参数 / BOOL静默 / 全局lastError / 裸BOOL）。
旧函数继续保留旧签名，新 ops 层在内部翻译成 BM_RESULT。

### 1.4 编码策略（消灭乱码的根）

| 边界 | 编码 | 转换函数（utils/strconv.c） |
|------|------|------------------------------|
| 程序内部 | UTF-16 (WCHAR) | — |
| 源文件 | UTF-8 **with BOM** | — |
| 控制台子进程输出（bcdedit 等） | OEM 代码页 | `OemToWide()` |
| 磁盘上的文本（limine.conf 等） | UTF-8 | `WideToUtf8()` |

禁止在业务代码里直接调 `MultiByteToWideChar`，一律走 helper，codepage 显式可见。

### 1.5 环境能力探测（core/envinfo.c，规划）

启动时探测一次，产出全局能力位，各页面据此禁用/降级：

```
BM_ENV {
    bool isAdmin;          // 管理员权限
    bool isWinPE;          // PE 环境（无 UAC / 无 Shell）
    bool hasBcdEdit;       // bcdedit 可用
    bool firmwareUefi;     // UEFI 固件（NVRAM API 可用）
    bool hasEsp;           // ESP 可达
}
```

### 1.6 测试策略

- 纯逻辑（MBR 解析、limine.conf 生成、BM_RESULT 格式化）抽成可离线调用的函数；
- debug 构建下磁盘访问经 `DISK_IO` 间接层，可指向镜像文件 → MBR 解析/改写可离线单测；
- CI（后续）：MinGW 编译 + 离线单测。

## 二、前端设计：卡片式简约 UI

### 2.1 设计语言

- **风格**：浅色、大留白、圆角卡片（8px）、细边框、轻阴影。参考 Fluent / shadcn 的克制感。
- **色板**（沿用现有青色主色，收敛为 6 色）：

| 用途 | 色值 |
|------|------|
| 背景 | `#F6F8FA` 冷灰 |
| 卡片 | `#FFFFFF` + 边框 `#E4E9EF` |
| 主色 | `#0EA5E9` 天青（操作/选中） |
| 文字主/次 | `#0F172A` / `#64748B` |
| 语义色 | 成功 `#22C55E` · 警告 `#F59E0B` · 危险 `#EF4444` |

- **字体**：微软雅黑 / Segoe UI。标题 17px 半粗，正文 13px，辅助 12px。
- **危险操作永远用红色实心按钮 + 卡片右上角红色徽标**，与普通操作视觉隔离。

### 2.2 信息架构：三级收敛为一二级

旧版 4 个侧边栏页面塞了太多平铺控件。新版以**卡片**为导航与分组单元：

```
┌──────────────────────────────────────────────────────────┐
│  ⬡ Boot Manager Pro                        [系统状态胶囊] │
│                                                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐   │
│  │ 🖥 引导管理    │  │ 📦 引导器安装 │  │ 🛟 备份恢复   │   │
│  │              │  │              │  │              │   │
│  │ 5 个启动项    │  │ rEFInd 未装  │  │ 上次备份 3天前 │   │
│  │ 默认: Win11  │  │ Limine 未装  │  │ 12 个备份点   │   │
│  │              │  │              │  │              │   │
│  │        管理 →│  │        安装 →│  │        查看 →│   │
│  └──────────────┘  └──────────────┘  └──────────────┘   │
│                                                          │
│  ┌─ 系统概览 ──────────────────────────────────────────┐ │
│  │  磁盘 0 · MBR · 512GB    │  固件 UEFI · 已管理员运行  │ │
│  └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

**首页 = 状态仪表盘**：每张卡片顶部是入口名，中间两行**实时状态摘要**
（这是关键差异：旧版要点进去才知道状态），右下角动词按钮。

点击卡片进入该功能的**工作页**，工作页内部也用卡片分组：

```
引导管理工作页
┌─ 启动顺序 ──────────────────────────────────────┐
│  ⠿ 1  Windows 11        \EFI\...\bootmgfw.efi  │
│  ⠿ 2  rEFInd            \EFI\refind\...        │   ← 列表项也是
│  ⠿ 3  UEFI: USB Drive   可移动设备              │     行卡片：悬停
│          [ 上移 ] [ 下移 ] [ 设为默认 ] [ 删除 ]  │     浮起 + 操作钮
└─────────────────────────────────────────────────┘
```

设计规则：

1. **一卡一事**：一张卡片只回答一个问题（"当前引导器是什么""上次备份是什么时候"）。
2. **状态前置**：所有列表型信息在首页就给摘要，工作页才给全量。
3. **破坏性操作二段式**：删除/恢复/重装一律弹确认卡（非系统对话框），红色主按钮。
4. **操作反馈就地显示**：卡片内嵌状态条（成功绿/失败红），不打断式弹窗。
5. **键盘/无障碍**：卡片可 Tab 聚焦、Enter 触发、聚焦态 2px 主色描边。

### 2.3 实现方式（Win32 无框架）

- 自绘卡片控件 `src/ui/cards.c`：注册 `BMCardClass`，`WM_PAINT` 里
  `RoundRect` 画圆角 + GetSysColor 式色板，`WM_MOUSEMOVE/TRACK` 做悬停浮起
  （边框加深 + 1px 下移阴影），点击发 `WM_COMMAND` 给父窗口。
- 卡片内容用子区域绘制：图标(可选) + 标题 + 摘要行 ×2 + 动作按钮。
- 列表行卡片 = ListView 换自绘 `WM_DRAWITEM` 行，或直接卡片容器内自绘行。
- 不引第三方库；GDI 足够，深色模式留接口（色板是常量表，换表即可）。
